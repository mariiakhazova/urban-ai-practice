## Оставшиеся ограничения

### 1. Производительность перебора кварталов

**Проблема:** Автоматический перебор 403 кварталов занимает 5–10 минут.

**Причина:** Для каждого квартала вызывается `competitive_provision` из BlocksNet, который решает LP-оптимизацию. 403 × ~0.5–1.5 секунды = 5–10 минут.

**Обход:** Добавлен прогресс-бар и счётчик кварталов для обратной связи.

**Возможные оптимизации (не реализованы):**
- Кэширование промежуточных результатов
- Параллелизация расчётов (multiprocessing)
- Предварительный расчёт базового дефицита (уже реализован)
- Ограничение перебора только populated кварталов

---

### 2. Требование интернета для подложки карты

**Проблема:** OpenStreetMap требует интернет-соединение для загрузки тайлов.

**Влияние:** Без интернета подложка карты не отобразится (серый фон).

**Обход:** Геометрия кварталов, школы, границы города и цветовая визуализация остаются доступными. Расчёты не зависят от карты.

**Примечание:** Условия использования OpenStreetMap требуют атрибуции (автоматически добавляется Folium).

---

### 3. Отсутствие кнопки "Отмена" для перебора

**Проблема:** Нет возможности прервать автоматический перебор после нажатия кнопки.

**Влияние:** Пользователь должен дождаться завершения перебора (5–10 минут).

**Возможное решение (не реализовано):** Добавить кнопку "Отменить" и проверку `if stop_requested: break` в цикле перебора.

---

### 4. Ограничение сравнения до 3 сценариев

**Проблема:** Вкладка "Сравнение" хранит только последние 3 сценария.

**Причина:** Реализация в `app.py:454-455, 492-493` ограничивает список сценариями: базовый, ручной выбор, автоматический подбор.

**Влияние:** Незначительное — пользователь может сравнивать только 3 сценария одновременно.

---

### 5. Использование `@st.cache_resource` в авто-размещении

**Проблема:** Ранее использовалось `@st.cache_resource` для функции `run_auto_placement`, что блокировало обновление прогресса.

**Исправление:** Убрано кэширование для функции с прогрессом.
